# ADR 001 — Clean Architecture (Api / Application / Domain / Infrastructure)

**Context:** Backend'in iş mantığı, web çatısı, kalıcılık ve dış sağlayıcılardan (storage, AI) bağımsız test edilebilir ve değiştirilebilir olması gerekiyordu. **Alternatives:** tek katmanlı "fat controller" / klasik N-tier (DAL'a doğrudan bağımlılık). **Decision:** Clean Architecture — `Api → Application → Domain`, `Infrastructure` dışa bakan implementasyonları sağlar; Application yalnız interface tüketir. **Reasoning:** bağımlılık tersine çevrilince storage (Local↔S3) ve AI sağlayıcıları (Ollama↔Gemini) iş mantığına dokunmadan değiştirilebiliyor; birim testler altyapı olmadan koşuyor. **Consequences:** biraz daha fazla interface/boilerplate; karşılığında yüksek test edilebilirlik ve net bağımlılık yönü. Application'ın Infrastructure'a bağımlı olmaması **değişmez kuraldır**.
